# Tile builds

A build normally runs on the globe: 12960 × 17280, ~900 MB per channel per
snapshot, ~117k fronts. A **tile build** runs the same five steps on one
720 × 720 block — 518k pixels, a few hundred fronts, and no global pass
anywhere in it.

```bash
build-fronts --config configs/run/run_tile330.yaml --steps gradb2,find,group
build-fronts --config configs/run/run_tile330.yaml --steps colocate
```

This is not a crop of a global build (that is [a scene](../README.md#scenes)).
Nothing global is computed: the fields themselves are generated one tile at a
time.

## What makes a run a tile run

A `tile:` block under `source:`. Its presence is the switch.

```yaml
source:
  pipeline: "OSN"
  tile:
    index: 330          # or i: 13320, j: 9720   or   lon: -121.9, lat: 36.8
    root: "../../tiles"
    mask_land: true
```

Tiles are the 18 × 24 grid of 720 × 720 blocks the rect grid divides into,
row-major — the same numbering `dbof.tiles` uses. `index` and `i`/`j` are
arithmetic; `lon`/`lat` is resolved by dbof against the grid store and needs
network. All three resolve to the tile's origin, so two configs naming the same
tile record the same provenance.

`tile:` is this repo's key. It is stripped before the `source:` block is handed
to dbof, which only knows about global runs.

## What each step does differently

| step | global | tile |
|---|---|---|
| `gradb2` | build `frontal_structure.zarr` on S3 (a dbof run) | `generate-tile` the gradb2 field, one NetCDF per snapshot |
| `find` | — | — |
| `group` | — | — |
| `colocate` | build every missing subset store | `generate-tile` each channel to co-locate |
| `push` | copy the products to S3 | refused: there is nothing to sit beside |

`find` and `group` are unchanged, and deliberately so. They take arrays; the
array is smaller. Same code, same config, same store.

Generation is skipped per channel per snapshot when the NetCDF is already
there, so an interrupted series resumes. Each channel goes through one
`tile_utils.run_series` call, which resolves the tile and downloads its grid
once for the whole date list rather than once per snapshot.

## Where the fields live

```
{source.tile.root}/{YYYYMMDD_HHMMSS}/{channel}_tile{idx:03d}.nc
```

Named by this repo rather than by `generate-tile`'s own convention, so a build
can find a file again without knowing what hour resolved to what name. Each is
a single-channel NetCDF carrying 2-D `XC`/`YC`, which is where a tile build
gets its coordinates — there is no global grid read at all.

`--steps gradb2` on a config listing three subsets generates **only** gradb2.
The other channels are generated by `colocate`, when something actually wants
them.

## Ice masking

`ice_mask_find` / `ice_mask_props` need an `SIarea` tile for the same snapshot.
Setting `ice_mask_find` makes the `gradb2` step generate it alongside gradb2.

## The store

Identical, at tile shape: `binary`, `binary_unprocessed`, `labels`, and the
`geometry` / `properties` / `cross_properties` tables, keyed by snapshot, in
one zarr store. Rasters are chunked at `min(CHUNK, shape)`, so a 720 × 720
raster is one chunk instead of a chunk grid reaching past its own edge.
`store.attrs['tile_index']` records which tile.

Everything in [docs/store.md](store.md) applies unchanged — a reader cannot
tell a tile build from a global one except by the shape and that attribute.

## Tile-local thresholding

Worth knowing before comparing a tile build against a global one.

The threshold is a **local percentile over a 64 px window**, so the two agree
in the tile's interior and disagree within ~32 px of its edge, where the tile
has no neighbourhood to take a percentile over. Labelling differs there too: a
front crossing the boundary is one component globally and a stub locally, and
its `length_km` is measured on the stub.

`generate-tile` also NaNs an `edge_margin` rim (3 cells for gradient fields),
since horizontal stencils are invalid on a single face with no connections.

Neither matters for a time series over one region, which is what a tile build
is for. Both matter if the tile is a sample meant to stand in for the global
statistics.
